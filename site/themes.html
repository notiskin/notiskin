Making themes

A theme is a short list of colors and a few other choices. Notiskin turns it into styling for Notion. You can make one with pickers, or by writing the list yourself.

Make one in two minutes

  1. Open Notiskin, go to Themes and press New theme.
  2. Give it a name, then pick colors. Notion changes while you pick, and goes back to your normal theme when you close the editor. The small preview next to the pickers shows the same thing if Notion isn't open.
  3. Press Save. The theme is now a file in your themes folder (~/.notiskin/themes) and shows under Your themes. Pick it to use it.
  4. To make a dark version, switch to the Dark tab and pick colors there. Notion uses them when it is in dark mode.
  5. Edit on a theme card opens the same editor on a theme you already have. A theme you installed from the marketplace is updated by the marketplace, so editing one makes your own copy next to it.

The editor only changes the lines it owns. Open "The CSS itself" under the pickers to see or write the file by hand, comments and anything the pickers don't know stay exactly as you wrote them.

How a theme is written

A theme is a CSS file with one block called :root. Inside it, you set variables that start with --ns-:

/* Midnight */
:root {
  --ns-bg: #1a1a1a;
  --ns-sidebar-bg: #111111;
  --ns-text: #e0e0e0;
  --ns-title-text: #ffffff;
  --ns-link-color: #7eb8f7;
}

That is the whole format. Colors can be written any way CSS allows: #1a1a1a, rgb(26, 26, 26), hsl(0 0% 10%), oklch(...), color-mix(...), gradients, or another variable with var(--ns-bg).

A theme you keep for yourself can contain any CSS at all. The strict rules in What the marketplace accepts only apply when you publish it.

Fonts

Three variables take a font list. Names with spaces go in double quotes, and you can list up to 8, best first, ending with a general family like serif or sans-serif:

:root {
  --ns-font: "Inter Display", "Helvetica Neue", sans-serif;
  --ns-font-title: Georgia, serif;
  --ns-font-code: "JetBrains Mono", Menlo, monospace;
}

A font list can only pick a font that is already installed on the Mac that is using the theme. Nothing is downloaded, so choose fonts most people have, and end with a general family so there is a fallback. If you set no font variable, every font stays Notion's. Setting --ns-font changes titles too, unless you set --ns-font-title. Emoji and code keep their own fonts.

Light and dark

Put what is shared in :root, and what differs in a block that follows the Mac's (and Notion's) light or dark setting. Notion's own Light / Dark choice counts, not only macOS.

:root {
  --ns-bg: #ffffff;
  --ns-text: #1a1a1a;
}
@media (prefers-color-scheme: dark) {
  :root {
    --ns-bg: #1a1a1a;
    --ns-text: #e0e0e0;
  }
}

You can use dark and light once each. In the editor, the Dark tab writes this block for you.

What the marketplace accepts

Every theme you publish is checked by software first. A theme that passes is listed straight away, and it is used by everyone who installs it, so the check is strict. A theme that doesn't pass isn't rejected: it waits for a person to read it, and the reason is shown in your Submissions.

What passes

  • Only variables whose names start with --ns- (letters, numbers and dashes after that), inside :root.
  • Optionally the whole :root block wrapped in @media (prefers-color-scheme: dark) or light, at most one of each. Nothing else may be inside, and no other media query is allowed.
  • Values made of letters, numbers, spaces and # % . , + - * / ( ) !.
  • Functions from this list only: rgb rgba hsl hsla hwb lab lch oklab oklch color color-mix var calc min max clamp and the gradients (linear-gradient, radial-gradient, conic-gradient and their repeating- versions).
  • The three font variables (--ns-font, --ns-font-title, --ns-font-code) may hold up to 8 font names: a name in double quotes (letters, numbers, spaces and dashes, up to 40 characters) or a plain word like Georgia. Nothing else in them: no brackets, colons, semicolons, slashes or var().
  • No more than 20,000 characters in total.

What waits for a person

Anything else: url(), image-set(), @import, other selectors or properties, quotes in any variable that isn't a font variable, backslashes, other functions, and nested rules. Images are not allowed in marketplace themes on purpose.

Publishing and versions

  1. Sign in with GitHub in Settings. Publishing and rating need an account, installing doesn't.
  2. In the editor press Save and publish (or open the Publish tab and paste the CSS). Give it a name (letters, numbers and spaces, up to 50), a description, up to 3 tags, and optionally a link to a GitHub repository or gist.
  3. Press Submit. A theme that passes the check is listed at once. Otherwise it waits for a reviewer. Submissions shows where each one is and why.

The tags to choose from are: dark, light, minimal, colorful, productivity, fun, accessibility, fonts. You can publish 5 things per hour (themes and plugins together).

New versions

Once a theme is listed you can improve it. On the Publish tab, Publish a new version takes the new CSS and a line about what changed. A new theme version that passes the check goes live at once, and everyone who installed the theme sees an Update button. If it doesn't pass, it waits for review and the version people have stays live meanwhile. You can have one waiting version at a time, and only you can publish versions of your own theme.

Tags and the link can be changed later without review, from the same Publish tab.

After it is listed

  • People find it in Browse, sorted by newest, top rated or most downloaded, and filtered by tag. Installing adds it to their themes, it doesn't switch to it.
  • Anyone signed in can report a theme. When three different accounts that are at least a day old report one as harmful, it is hidden from Browse automatically until a reviewer looks. Reviewers can also hide an item. Copies people already installed aren't touched, and they see a warning on the card.
  • Download counts count one install per person per day, and only for signed-in installs.
