## Decisions already made

- The button lives in **Settings**, in a new "Notion" section.
- **No background watcher from the app.** After a Notion update the status shows "Needs repair" and the user clicks **Repair**. The CLI's `watch:install` stays as it is for CLI users.
- `npm run patch` / `npm run unpatch` keep working exactly as today.

## Why this is needed

Today only the CLI can patch. `patchNotion(nodePath, cliScriptPath)` writes a wrapper that runs `"<nodePath>" "<cliScriptPath>" inject`, and the CLI passes its own Node binary and `dist/cli/index.js` from the repo checkout. People who installed the DMG have neither, so they can't keep themes across Notion restarts.

## How it should work

### The wrapper in the packaged app

- In the desktop app, run the injector with the app's own binary in Node mode. `ensureInjector()` in `src/core/library.ts` already does this: `process.execPath` with `ELECTRON_RUN_AS_NODE=1` and the CLI at `join(__dirname, '..', 'cli', 'index.js')`, which works from inside `app.asar`.
- `makeWrapperScript` needs to be able to set `ELECTRON_RUN_AS_NODE=1` on the inject line. Keep the CLI's output byte-for-byte the same, so `isWrapperPresent` and existing installs are unaffected.
- The `exec "$(dirname "$0")/Notion.real" ...` line must keep working even if Notiskin.app is later moved or deleted. Notion must always start, only the theming may fail.

### Getting admin rights with one prompt

- Run the existing CLI `patch` command as root through one macOS password dialog:
  `osascript -e 'on run argv' -e 'do shell script (item 1 of argv) with prompt (item 2 of argv) with administrator privileges' -e 'end run' <command> <prompt text>`
  Pass the command and the prompt as arguments (`argv`), never by pasting them into AppleScript source.
- The command is `SUDO_USER=<current user> ELECTRON_RUN_AS_NODE=1 <execPath> <cli> patch`, with every value shell-quoted by a small helper (single quotes, `'` → `'\''`). Unit-test the quoting with paths that contain spaces, quotes, and `$`.
- Why `SUDO_USER`: an `osascript` admin command runs as root and can't be relied on to set it. `src/utils/constants.ts` uses it to find the real home folder (otherwise `~/.notiskin` would be `/var/root/.notiskin`). `patchNotion` also uses it to install the sudoers rule for silent re-signing and to chown the signing helper back to the user.
- The prompt text should name Notiskin, e.g. "Notiskin wants to install into Notion so your themes load every time Notion starts."
- Cancelling the dialog is a normal outcome (osascript error -128). Report "Cancelled", not a failure.

### File ownership (verify on a real Mac)

Patching as root can leave root-owned files inside `/Applications/Notion.app`: the wrapper, and files `codesign` rewrites. Notion's own updater runs as the user and may then fail to update. After patching and re-signing as root, give the bundle back to whoever owned `Notion.app` before (`stat` it first, then `chown -R owner:group`). The existing `sudo npm run patch` path has the same problem, so fix it in `patchNotion` for both.

### Status

Add a status check in `src/patcher/index.ts`. It must not need root:
- `not-installed`: Notion found, no wrapper
- `installed`: the wrapper is present and the program it points at exists
- `needs-repair`: `Notion.real` exists but the wrapper is gone (a Notion update replaced it), or the wrapper points at a program that no longer exists (Notiskin was moved or deleted)
- `notion-missing`: no Notion.app in `/Applications` or `~/Applications`

### Server endpoints (`src/gui/server.ts`)

- `GET /api/notion/status`, `POST /api/notion/install` (also used for Repair), `POST /api/notion/uninstall`.
- They sit behind the existing `/api` token check like every other route. No request body is used to build the command.
- Only on macOS (`process.platform === 'darwin'`); otherwise return a clear error.
- One install/uninstall at a time (a simple in-progress flag), so double clicks don't run two password prompts.
- Don't break the CLI or the standalone `npm run gui` server: outside Electron, `process.execPath` is Node, and `ELECTRON_RUN_AS_NODE` is harmless there.

### Settings UI (`src/gui/settings.html`)

- A "Notion" section with the status in plain words and one button: **Install**, **Repair**, or **Uninstall**, depending on the status.
- Before installing, explain in one line that macOS will ask for the password and that Notion will restart.
- After install or repair, offer to restart Notion. Quitting Notion closes the user's windows, so ask first.
- Show errors in plain words. Point to `~/.notiskin/logs/inject.log` for details.

### Tests

- Unit tests (`test/*.test.js`): wrapper text for CLI mode (unchanged) and app mode, shell quoting, status detection against a temp folder that imitates `Notion.app/Contents/MacOS`.
- Add an env override for the Notion location, used by tests only (e.g. `NOTISKIN_NOTION_APP`), so tests can patch a copy of the fake Notion in a temp folder. Never `/Applications`.
- macOS integration test (CI only): copy the fake Notion app to a temp folder, patch it without root (call `patchNotion` directly), check the status says `installed`, launch it and check the debug port comes up, then unpatch and check the status says `not-installed` and the original binary is back byte-for-byte.
